# 📌 ENTERPRISE DATA COMPILER — AI CODING CONTEXT PROMPT

---

## 🧠 PROJECT DEFINITION (IMPORTANT)

You are building an **Enterprise Data Compiler System**.

The system transforms messy enterprise data (CSV/Excel) into structured business models  using LLM-generated declarative Intermediate Representation (IR), a deterministic validation layer (Harness), and a native compiler runtime. 
AI DOES NOT write or execute raw Python code.

This is NOT a chatbot, NOT an agent system.

It is a **data transformation compiler system**.

---

## 🎯 CORE OBJECTIVE

Implement an end-to-end pipeline:

```text id="core_flow"
Raw CSV/Excel
    ↓
Schema Profiling Layer
    ↓
LLM Mapping Engine (generate structured IR JSON)
    ↓
IR Validator (Harness Pre-check)
    ↓
Native Compiler Execution (Vectorized Pandas Operators)
    ↓
Harness Validation (strict rules + stats)
    ↓
Sandbox execution
    ↓
Human review output
    ↓
SQLite structured output
```

---

## ⚠️ IMPORTANT DESIGN CONSTRAINTS

1. AI MUST NOT directly modify database
2. 2. AI MUST NOT generate executable programming code (Python/SQL). AI ONLY generates declarative Transformation IR specifications conforming to a strict JSON schema.
3. Execution must be entirely driven by white-listed, pre-defined native operators. No exec() or eval() mechanisms are permitted in the system.
4. All AI outputs MUST be validated by Harness before execution
5. System must be deterministic and auditable
6. No multi-agent system, no autonomous planning loops

---

## 🧱 SYSTEM ARCHITECTURE (8 LAYERS)

You MUST implement all layers as separate modules.

---

### LAYER 1 — CONNECTORS

Purpose:
Load raw enterprise data.

Support:

* CSV
* Excel

Output:

* pandas DataFrame

---

### LAYER 2 — SCHEMA PROFILER

Purpose:
Analyze dataset structure.

Output schema profile JSON:

```json
{
  "fields": {
    "amount": {
      "type": "number",
      "null_ratio": 0.01,
      "min": -10,
      "max": 1000
    }
  }
}
```

---

### LAYER 3 — BUSINESS ONTOLOGY

Purpose:
Define target structured business schema.

Example:

```json
Customer {
  customer_id: string,
  customer_name: string,
  phone: string
}
```

This is STATIC in MVP.

No graph DB required.

---

### LAYER 4 — LLM MAPPING ENGINE (CRITICAL)
Input: Source schema, target ontology. 
Output: Strict Transformation IR (Intermediate Representation) JSON.  
- Must specify target fields, trusted operations (COPY, CONCAT, ADD, etc.), and typed input arguments (COLUMN_REF or LITERAL).
- Absolutely no code blocks or dynamic expressions allowed.

---

### LAYER 5 — HARNESS VALIDATION (SAFETY GATE)
This layer acts as a two-phase gateway:
- Phase 1 (Pre-execution Topology Check): Validates the LLM-generated IR against the target ontology fields and source schema column names before compilation. Catches field hallucinations or invalid operator arguments.
- Phase 2 (Post-execution Data Check): Validates the compiled output DataFrame against deterministic business rules (e.g., non-negative constraints) and statistical metrics (e.g., row count/sum consistency).  

---

### LAYER 6 — DETERMINISTIC COMPILER RUNTIME
Purpose: Safely compile and execute the validated IR.
* No Sandbox Required: Since no arbitrary Python code is executed, OS-level containment is obsolete.   
- Mechanism: Translates the declarative IR instructions into deterministic, native, vectorized Pandas operations.
- Error Handling: Handles computational exceptions (e.g., division by zero, non-numeric strings) gracefully via vector type coercion without halting the system.

---

### LAYER 7 — HUMAN REVIEW MODULE

Purpose:
Expose validation results.

Output:

* mapping result
* validation report
* execution summary

Allow:

* approve
* reject
* modify rules

---

### LAYER 8 — OUTPUT LAYER

Write clean structured data to:

* SQLite database (primary)
* CSV export (secondary)

---

## 🔁 END-TO-END PIPELINE RULE

The system MUST implement a single orchestrator:

```text
run_pipeline(input_file):
    run_pipeline(input_file, target_ontology):
    load raw data (Layer 1)
    profile schema attributes (Layer 2)
    call LLM mapping engine to generate IR Specification (Layer 4)
    validate IR topology via Harness Pre-check (Layer 5 Phase 1)
    if fail → reject IR and return compilation error
    compile IR and execute via Deterministic Compiler (Layer 6)
    validate output data via Harness Post-check (Layer 5 Phase 2)
    if pass → write to SQLite/CSV (Layer 8)
    else → route anomalous records to Quarantine DB for Human Review (Layer 7)
```
